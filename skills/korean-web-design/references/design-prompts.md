# 디자인 작업을 요청하는 프롬프트

## 먼저 채울 다섯 줄

- 누가 어떤 상황에서 쓰는가?
- 사용자가 처음 해야 할 일과 마지막에 확인할 결과는 무엇인가?
- 화면에 반드시 들어갈 실제 콘텐츠의 종류와 가장 까다로운 값은 무엇인가?
- 이미 결정한 제품 동작과 설계자가 자유롭게 결정할 부분은 무엇인가?
- 어느 화면 크기와 입력 방식에서 어떤 행동까지 확인해야 하는가?

## 새 시안을 요청할 때

> [사용자]가 [상황]에서 [작업]을 끝내고 [결과]를 확인하는 화면을 만들어. 첫 화면에서 사용자가 알아야 할 정보와 가장 먼저 할 행동을 정해. [대표 콘텐츠]와 [길거나 비어 있는 값]을 넣고 제목, 본문, 이미지, 버튼의 우선순위를 잡아. 레퍼런스를 쓴다면 가져올 상호작용 하나와 적용할 장면을 설명해. 실제 문구를 넣은 화면을 렌더해서 본 뒤 수정해.

## 여러 안을 비교할 때

콘텐츠, 필수 동작, 완료 조건을 통일한다. 각 안에는 사용자가 **무엇을 보고 어떤 단위로 결정하는지**에 관한 가설을 하나씩 준다. 색이나 서체를 정하기 전에 가설에 따라 어느 장면의 조작이 달라지는지 확인한다. 첫 화면, 반복 작업 중, 완료 후의 같은 장면을 나란히 비교한다.

> 각 가설로 첫 행동부터 완료까지 구현해. 처음 보는 사람이 설명 없이 차이를 경험할 수 있게 해. 공통 과제를 수행해 보고 어느 안에서 어떤 판단이나 조작이 쉬워졌는지 보여 줘.

## 마음에 든 초안을 이어서 만들 때

> 기존 화면을 먼저 실행해. 유지할 구도·정보 위계·핵심 조작을 짚고, 중간에 끊긴 흐름을 끝까지 연결해. 바꾸기 전후를 같은 크기와 같은 콘텐츠로 찍어 비교해. 입력하거나 되돌아간 뒤에도 다음 행동을 이어갈 수 있는지 확인해.

## 화면을 보고 고칠 때

스크린샷을 직접 열어 가장 먼저 눈에 들어온 요소와 의도한 주 행동이 일치하는지 본다. 한국어 제목이 두 줄이 되었을 때의 위계, 긴 레이블과 큰 글자에서 버튼의 위치, 이미지의 주요 피사체가 잘리는 지점을 살핀다. 가장 큰 문제부터 고친 뒤 같은 조건에서 다시 확인한다.

기기 폭과 입력 방식은 대상 사용자에 맞춰 고른다. 모바일에서는 한 손 조작, 키보드를 연 상태의 제출, 뒤로 가기와 위치 복귀를 직접 수행한다. 넓은 화면에서는 추가 공간이 읽기·비교·작업에 쓰이는지 확인한다. 검증 기록에는 실행 환경과 관찰한 결과를 적고 실기기 검증 여부를 구분한다.

## 공개 가이드로 옮길 때

공유할 수 있는 것은 다른 제품에도 적용할 판단 기준과 빈칸 템플릿이다. 비공개 작업에서 배운 점은 일반적인 질문으로 다시 작성한다. 원문 지시, 코드, 스크린샷, 시연 파일, 저장소 주소, 사용자 데이터는 해당 프로젝트 안에 보관한다.
