# 한국어 조판과 문구

| 증상 | 먼저 확인할 것 | 비교 방법 |
|---|---|---|
| 넓은 화면에서도 제목 끝에 두세 글자만 남는다 | JSX의 br, 문구에 들어간 개행, 제목 상자의 실제 너비 | 같은 문구에서 강제 개행을 공백으로 바꾼다. 짧은 제목에만 text-wrap: balance를 시험하고 기본 줄바꿈에서도 읽히는지 본다. |
| 한글이 뭉치거나 영문·숫자만 튄다 | 브라우저의 Rendered Fonts에서 문자별 실제 서체, 요청한 굵기와 제공 파일, 과도한 음수 자간 | 시스템 고딕과 Pretendard를 같은 크기·굵기·행간에서 비교한다. 제목과 본문을 따로 평가한다. 자체 호스팅 시 첫 다운로드 크기와 웹폰트 교체 후 줄 수도 확인한다. |
| 좁은 화면에서 단어가 깨지거나 큰 빈칸이 생긴다 | word-break, overflow-wrap, flex/grid 자식의 최소 폭 | 설명문에는 어절 단위 keep-all을 시험하고, 긴 URL·식별자에는 anywhere를 시험한다. 사용자 캡션의 의도된 개행은 보존한다. 괄호·구두점·조사·단위를 실제 문장으로 확인한다. |
| 글자가 작거나 확대하면 버튼이 잘린다 | 글꼴별 체감 크기, 고정 높이, nowrap, 말줄임 | 본문은 1rem과 1.0625rem을 출발값으로 비교한다. 상대 단위와 단위 없는 행간을 쓰고, 여러 줄 레이블도 버튼 높이를 늘릴 수 있게 한다. |

**문구**　버튼을 읽으면 결과를 예상할 수 있게 쓴다. 예를 들어 ‘확인’은 상황에 따라 ‘링크 복사’ 또는 ‘변경 저장’이 된다. 오류 안내는 사용자의 입력이 보존됐는지, 지금 할 수 있는 행동이 무엇인지 알려 준다. 서비스에 구현된 동작과 대조한다.

**검증용 입력**　‘11월 모음’, ‘2026년 11월 작업 기록 (두 번째 모음)’, ‘가을산책사진모음집최종수정본’, ‘PDF 12개 · 1.8GB’, 붙여 넣은 긴 URL을 시험한다. 320px와 일반 휴대전화 폭, 데스크톱, 글자 확대 200%에서 가려진 조작과 수평 스크롤을 확인한다. 데스크톱의 폭 모사와 실기기 한글 입력·폰트 렌더 결과를 따로 적는다.

**원본 자료**　당근 SEED에서 제목·본문의 역할별 스타일과 시스템 폰트의 플랫폼 차이를, KRDS에서 같은 크기의 글꼴이 다르게 보이는 사례를 참고한다. 한글 금칙과 어절 처리의 배경은 KLREQ를 본다.
